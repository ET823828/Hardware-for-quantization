\section{Project Overview}
%% ================================================================

This project is based on \textbf{Example Project 4 (Quantization)}.

\subsection{Problem and Motivation}

LLM inference is memory-bandwidth bound: during autoregressive decoding the entire weight matrix must be streamed from HBM for every token. 4-bit weight quantization achieves a 4$\times$ reduction over BF16, and all major vendors have responded---NVIDIA introduced NVFP4 with Blackwell, and the Microscaling standard (MXFP4) is gaining cross-vendor adoption.

However, these schemes are \textbf{bundled, one-size-fits-all solutions} designed for general-purpose GPUs. Each implicitly fixes the entire MMA datapath: operand format, number of rescale levels, per-level granularity, scale-factor precision, and accumulator precision. These choices are conservative to guarantee numerical safety across arbitrary workloads. For a \textbf{domain-specific accelerator targeting known workloads}, this conservatism leaves significant efficiency on the table.

We focus on \textbf{FFN/MLP layers} as the target workload because they account for approximately two-thirds of total model parameters and a comparable share of FLOPs in standard transformer architectures. During autoregressive decoding these large weight matrices dominate memory bandwidth and energy consumption, making FFN the primary efficiency bottleneck for 4-bit quantization.

Our preliminary AccelForge modeling already supports the core motivation. In a representative NVFP4-style W4A4 pipeline (Figure~\ref{fig:energy}), the \textbf{combined rescale stages dominate total energy}, while quant/scale preprocessing is negligible. Extending this to an inference-faithful sweep over four Llama-2-7B FFN-like shapes, we find that W4A4 inference reduces \emph{decode} energy by 9.8--10.5\% and latency by 41.2--41.3\% versus FP16, but for \emph{prefill} it still increases energy by 26.0--27.2\% even while cutting latency by 70.3--71.1\%. This gap between the realized design and the ideal no-overhead quantized lower bound directly motivates rescale-pipeline optimization.

Recent works have made isolated improvements along individual pipeline dimensions---HiFloat4 \cite{hifloat4} proposes a fixed three-level scaling hierarchy, AXE \cite{axe} treats accumulator precision as tunable, MixPE \cite{mixpe} explores dequantization placement, and ``Is Finer Better?'' \cite{isfiner} analyzes block-size/scale-format interactions. However, each produces a single new hand-designed point in the space, fixing all other dimensions. \textbf{The problem has never been formulated as a joint design-space exploration (DSE)}: no prior work decomposes these dimensions into an orthogonal search space and systematically evaluates the accuracy--hardware-cost tradeoff across configurations.

\subsection{Key Questions}

\textbf{Core question:} Can we formulate the design of a 4-bit MMA rescale pipeline as a structured DSE problem---defining the search space (orthogonal pipeline dimensions), the search method (systematic sweep with pruning), and the evaluation metric (joint accuracy--hardware-cost)---such that this formulation is both \emph{valid} (contains configurations dominating all existing bundled schemes) and \emph{necessary} (the optimal configuration is workload-specific, so no single bundled scheme can be universally optimal)?

Our contribution is not a single better configuration, but \textbf{the problem formulation itself}: the decomposition of the bundled pipeline into a tractable search space, paired with a hardware-aware evaluation framework. The finding that optimal configurations are workload-specific validates this formulation---it proves that hand-designed one-size-fits-all schemes inherently leave efficiency on the table.

\subsection{Hypotheses}

\begin{enumerate}
    \item \textbf{FP32 rescale is over-provisioned} for many FFN GEMMs, particularly those with moderate accumulation chain lengths ($K \leq 4096$) and well-behaved weight distributions. Lower-precision rescale (FP16 or shift-only) can preserve accuracy at substantially lower energy.
    \item \textbf{Two-level scaling is not universally necessary.} For layers with low dynamic range, single-level scaling with an appropriate block size and scale precision can match accuracy while eliminating an entire rescale stage.
    \item \textbf{The optimal configuration is workload-specific.} Small-$K$, low-kurtosis layers tolerate aggressive precision reduction; large-$K$, heavy-tailed layers require conservative accumulation. This workload-dependence is the key validation of our framework---it proves no single bundled scheme can be universally optimal.
    \item We target $\geq 2\times$ \textbf{energy reduction} in the rescale/accumulation stages with $<$1\% accuracy degradation relative to NVFP4 for the workload-optimal configuration.
\end{enumerate}

All recent works share a common pattern: each proposes or optimizes one new fixed design without formulating the problem as a joint search. HiFloat4 fixes its three-level hierarchy as a single format; AXE optimizes accumulator precision in a software-only PTQ framework without hardware cost modeling; MixPE performs Pareto DSE over dequantization \emph{placement} but does not touch the internal rescale pipeline structure; M$^2$XFP \cite{m2xfp} and MX+ \cite{mxplus} enhance MX through metadata augmentation, each producing one new fixed scheme. Hardware-aware quantization (HAQ, mixed-precision NAS) searches over per-layer bit-width on \emph{fixed} hardware, not over the MMA pipeline structure.

\textbf{What's missing:} The problem has never been formulated as a structured DSE---decomposing the rescale pipeline into orthogonal dimensions, defining a tractable search space, and systematically evaluating the joint accuracy--hardware-cost tradeoff.

\subsection{Our Approach: Unbundling the Rescale Pipeline}

We decompose the 4-bit MMA datapath into independently tunable dimensions. We fix weight format (E2M1) and activation format (FP8 E4M3) and focus on the three core rescale-pipeline dimensions:

\textbf{Dimension 1: Rescale pipeline structure}---the number of rescale levels (0, 1, or 2) and block granularity at each level ($b \in \{16, 32, 64, \text{per-channel}\}$; for 2-level, coarse $B \in \{256, \text{per-channel}, \text{per-tensor}\}$). Finer granularity and more levels improve accuracy but add rescale operations and scale-factor storage.

\textbf{Dimension 2: Scale-factor format} (per level, independently)---FP32, FP16, BF16, FP8 E4M3, E8M0 (power-of-2 bit-shift, nearly free), or fixed-point. In a 2-level pipeline the fine and coarse levels may use different formats, e.g., E8M0 shift at fine level + FP16 at coarse level.

\textbf{Dimension 3: Accumulator precision}---FP32, FP16, BF16, INT32, or segmented (accumulate $N$ partial products in FP16, then reduce to FP32).

After pruning invalid combinations (e.g., accumulator precision $\geq$ operand precision), we estimate $\sim$50 viable configurations.

\subsubsection{Locating existing schemes}
Every existing scheme is a single hand-designed point in this space:
\begin{itemize}
    \item \textbf{NVFP4} = \{2-level (b=16, B=tensor), FP32 rescale $\times$2, FP32 acc\}
    \item \textbf{MXFP4} = \{1-level (b=32), E8M0 shift, FP32 acc\}
    \item \textbf{INT4-GPTQ} = \{1-level (g=128), FP16 dequant, FP32 acc\}
    \item \textbf{HiFloat4} = \{3-level (hierarchical), E6M2+E1+E1, FP32 acc\}
\end{itemize}

Our contribution is the \textbf{formulation itself}: decomposing the bundled pipeline into this search space, building the evaluation infrastructure (PyTorch accuracy emulation + AccelForge hardware cost modeling), and demonstrating that (a) all existing schemes are suboptimal, and (b) the optimal configuration is workload-dependent---validating the necessity of this DSE framework.

\subsection{Tradeoffs and Challenges}

\begin{itemize}
    \item \textbf{Search space tractability:} Pruning reduces the combinatorial space to $\sim$50 configurations, manageable for exhaustive sweep.
    \item \textbf{Design-time vs.\ runtime:} The accelerator fixes the pipeline at design time; a single configuration must cover all FFN layers, or we allow 2--3 switchable modes with accounted switching cost.
    \item \textbf{Scale-factor storage overhead:} Finer blocks increase scale-factor storage, reducing effective compression. This overhead is included in total efficiency metrics.
\end{itemize}

\section{Evaluation}

\subsection{Baselines and Fair Comparison}

We compare against INT4, MXFP4, NVFP4, and HiFloat4. All configurations use 4-bit weights with FP8 E4M3 activations; effective compression ratio (including scale-factor overhead) is reported. GEMM shapes are identical across configurations. Area is held constant or included via energy-delay-area product (EDAP). Accuracy is measured as per-layer output MSE relative to FP16 and end-to-end perplexity when feasible.

\subsection{Current Progress and Preliminary Results}

We have \textbf{completed Milestone 1} and completed the \textbf{hardware-cost portion of Milestone 2}. Concretely, the current notebook and AccelForge flow now support: (1) an FP16 baseline, (2) a prequantized weight-only W4A16 runtime, (3) an \emph{inference-faithful} W4A4 NVFP4-style runtime with prequantized weights and online activation quantization only, and (4) an ideal no-overhead W4A4 lower bound. We evaluated four FFN-like GEMM shapes derived from Llama-2-7B: decode-up, decode-down, prefill-up, and prefill-down.

Several findings are already useful for the final project. First, the naive prequantized W4A16 path is \emph{not} competitive on this architecture: explicit dequantization more than doubles decode energy and still slightly increases prefill energy. Second, the inference-faithful W4A4 model behaves qualitatively as expected for decode-time inference: the quantized compute path is faster and modestly lower-energy than FP16, but still 2.82--2.84$\times$ higher energy and 9.39--9.41$\times$ higher latency than the ideal no-overhead W4A4 lower bound. Third, prefill reveals a different regime: W4A4 reduces latency to 0.289--0.297$\times$ of FP16, but its energy remains 3.87--3.91$\times$ higher than the ideal lower bound because rescale dominates the realized cost.

These results are strong proposal evidence because they validate the central thesis while also sharpening it: \textbf{the opportunity is real, but the relevant bottleneck depends on workload regime}. Decode workloads already show end-to-end benefit from W4A4 on this architecture, whereas prefill workloads expose a large energy gap that is overwhelmingly due to online rescale. The software-accuracy half of Milestone 2 and the architectural optimization work of Milestone 3 remain open.

\subsection{Experiment 1: Energy Breakdown of Existing Schemes}

\textbf{Goal:} Quantify the energy cost of each MMA pipeline stage for baseline schemes, establishing that the rescale/accumulation overhead is significant and worth optimizing.

\textbf{Method:} Model a systolic-array MMA unit in AccelForge for each baseline. Decompose energy into: operand fetch, multiply, accumulation, rescale (per level), scale-factor fetch, and writeback.

\textbf{Class concepts:} Energy cost hierarchy (compute vs.\ data movement); multiplier energy scaling with bit-width.

\textbf{Metrics \& visualization:} Stacked bar chart---X-axis: scheme, Y-axis: energy per output element (pJ), segmented by pipeline stage. Area per MAC ($\mu$m$^2$) reported alongside.

\textbf{Current status:} The current W4A4 inference-faithful sweep already confirms the main trend: combined rescale stages account for 64.5--64.8\% of total W4A4 decode energy and 74.1--74.4\% of total W4A4 prefill energy, while quant/scale preprocessing is negligible. Extending this analysis to additional baselines such as MXFP4 and INT4 remains future work, but the key motivation for rescale-pipeline optimization is now empirically established.

\subsection{Experiment 2: Accuracy--Efficiency Pareto Frontier}

\textbf{Goal:} Sweep the design space and demonstrate that the Pareto frontier contains configurations dominating all existing bundled schemes.

\textbf{Method:} (1) \emph{Accuracy:} PyTorch emulator with configurable rescale pipeline; evaluate on FFN layers from Llama-2-7B and ViT-L; measure per-layer MSE. (2) \emph{Hardware cost:} AccelForge model for each configuration; extract energy per output element and area. (3) Overlay all configurations and baselines on the accuracy--energy plane.

\textbf{Class concepts:} Design-space exploration; Pareto optimality; precision--efficiency tradeoff.

\textbf{Metrics \& visualization:} Scatter plot---X-axis: energy/output (pJ), Y-axis: negative MSE. Pareto frontier curve highlighted; existing schemes as labeled reference points.

\textbf{Expected trend:} Configurations such as \{1-level b=16, E8M0 fine shift, FP16 acc\} or \{2-level b=16+channel, E8M0 fine + FP16 coarse, BF16 acc\} will match NVFP4 accuracy at lower energy. All four existing schemes will be interior to the Pareto frontier, demonstrating the value of unbundled pipeline design.

\subsection{Experiment 3: Workload-Specificity of Optimal Configuration}

\textbf{Goal:} Show that the optimal pipeline configuration varies with workload characteristics ($K$, weight distribution), validating that the DSE framework is \emph{necessary}---not just that better points exist, but that no single point is universally best.

\textbf{Method:} Select 3 configurations from the Pareto frontier (aggressive / moderate / conservative). Evaluate each on every FFN GEMM layer from Llama-2-7B and ViT-L, varying in $K$ and weight distribution. Map the per-layer optimal configuration to the feature space.

\textbf{Class concepts:} Workload characterization; accumulation chain length vs.\ required dynamic range; design-time specialization vs.\ one-size-fits-all.

\textbf{Metrics \& visualization:} (a) 2D scatter---X=$K$, Y=kurtosis, color=optimal configuration, revealing decision boundaries. (b) Table: percentage of layers where each configuration wins, by model. (c) Energy savings from per-layer-optimal assignment vs.\ best single fixed configuration.

\textbf{Expected trend:} Small-$K$ layers tolerate aggressive precision reduction (shift-only rescale, FP16 accumulator); large-$K$ layers require conservative settings. $K$ will be the strongest predictor. Cross-model analysis will confirm that workload features---not model identity---determine the optimal configuration.
