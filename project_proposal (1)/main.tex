\section{Project Overview}
%% ================================================================

This project is based on \textbf{Example Project 4 (Quantization)}.

\subsection{Problem and Motivation}

Modern AI workloads consists of two fundamentally different computational phases. \textbf{Prefill} processes the entire input prompt in a single forward pass with large batch dimension ($M \gg 1$), making it \textbf{compute-bound}: the energy and latency bottleneck lies in arithmetic operations, particularly the multiply-accumulate datapath. \textbf{Decode} generates tokens autoregressively with $M = 1$, making it \textbf{memory-bandwidth-bound}: the bottleneck is streaming the full weight matrix from HBM for every generated token. These two phases have radically different hardware utilization profiles---yet current 4-bit quantization schemes apply a single, fixed pipeline to both.

All major 4-bit formats---NVIDIA's NVFP4 (Blackwell), the Microscaling standard (MXFP4), and INT4 (GPTQ/AWQ)---are \textbf{bundled, one-size-fits-all designs}. Each implicitly fixes the entire MMA datapath: number of rescale levels, per-level granularity, scale-factor precision, and accumulator precision. On their native platforms these schemes are highly optimized: NVIDIA's Tensor Cores implement NVFP4 with deep microarchitectural tuning, achieving excellent throughput on Blackwell GPUs. However, the format-level design choices---FP32 rescale, two-level scaling, fixed block size---are conservative because GPU vendors must guarantee numerical safety across arbitrary workloads and both inference phases.

For \textbf{domain-specific AI accelerator design}, this one-size-fits-all constraint does not apply. When designing a custom accelerator for a known deployment scenario---a particular model family, a target prefill/decode ratio, a specific latency budget---the designer has the freedom to co-optimize the quantization format with the hardware datapath. Blindly adopting NVFP4 or MXFP4 as-is means inheriting conservatism that is unnecessary for the target workload. This is precisely the design scenario our framework addresses: \textbf{given a target workload, what is the optimal quantization pipeline to build into the hardware?} The answer, as we show, depends on the inference phase:

\begin{itemize}
    \item \textbf{During prefill}, the rescale pipeline dominates energy. Our AccelForge modeling of the NVFP4 W4A4 pipeline on Llama-style FFN GEMMs ($M{=}128$) shows that \textbf{rescale stages account for 74\% of total energy} (Figure~\ref{fig:energy}), and the full NVFP4 pipeline costs \textbf{1.27$\times$ the energy of an FP16 baseline}---quantization actually \emph{increases} energy during prefill despite the latency improvement. Cheaper rescale formats would directly address this bottleneck.
    \item \textbf{During decode} ($M{=}1$), memory bandwidth dominates. Here NVFP4 W4A4 achieves \textbf{0.90$\times$ energy and 0.59$\times$ latency} vs.\ FP16---both metrics improve, because 4-bit weights cut data movement in half. But the rescale overhead is still 64.5\% of W4A4 energy; compared to an ideal zero-overhead 4-bit multiply, the full pipeline costs $2.8\times$ in energy.
\end{itemize}

\begin{figure}[ht]
\centering
\includegraphics[width=0.85\columnwidth]{figures/energy_breakdown.pdf}
\caption{NVFP4 W4A4 energy breakdown for Llama-style FFN GEMMs. Rescale operations dominate in both phases: 74\% of energy during prefill ($M{=}128$), 64.5\% during decode ($M{=}1$). The core FP4 MatMul accounts for only 26--35\%.}
\label{fig:energy}
\end{figure}

These preliminary results reveal a striking asymmetry: \textbf{the same NVFP4 pipeline is energy-beneficial for decode but energy-harmful for prefill}. This directly motivates phase-adaptive quantization---using cheaper rescale for compute-bound prefill, while retaining the full pipeline for bandwidth-bound decode where the data-movement savings outweigh the rescale cost.

Recent works have made isolated improvements along individual pipeline dimensions---HiFloat4 \cite{hifloat4} proposes a fixed three-level hierarchy, AXE \cite{axe} treats accumulator precision as tunable, MixPE \cite{mixpe} explores dequantization placement, and ``Is Finer Better?'' \cite{isfiner} analyzes block-size/scale-format interactions. However, each produces a single new hand-designed point in the space, and \textbf{none considers the prefill/decode dichotomy}. The problem has never been formulated as a joint DSE that decouples the two phases and searches for phase-specific optima.

\subsection{Key Questions}

\textbf{Core question:} When designing an AI inference accelerator, can we define a structured search space over the 4-bit MMA rescale pipeline---decomposed into orthogonal dimensions (rescale levels, block granularity, scale format, accumulator precision)---and demonstrate that prefill and decode have \emph{different} Pareto-optimal configurations within this space, thereby justifying phase-adaptive quantization over adopting any single existing scheme as-is?

Our contribution is not a single better configuration, but \textbf{the search space definition and the phase-decoupling methodology} for custom accelerator design. The completed sweep shows that the preferred point changes across phases and workloads: LLM and VLA select different decode and prefill configurations, while VLM collapses to the same simple MXFP4-like point in both phases. This is the central validation---blindly adopting a general-purpose format like NVFP4 into a custom datapath leaves efficiency on the table, while a DSE can either choose a cheaper existing-style point or a phase-specific variant when the workload warrants it.

\subsection{Hypotheses}

\begin{enumerate}
    \item \textbf{Prefill favors cheaper rescale.} In the compute-bound regime (large $M$), the rescale pipeline is the dominant energy contributor. Lower-precision rescale (FP16, bit-shift) can achieve comparable accuracy at significantly lower energy.
    \item \textbf{Decode favors more aggressive quantization.} In the memory-bound regime ($M = 1$), configurations with coarser granularity or fewer rescale levels may be Pareto-optimal because bandwidth savings dominate.
    \item \textbf{The optimal configuration differs across both phases and workloads.} LLM, VLM, and VLA workloads have distinct GEMM shape profiles ($N$, $K$ dimensions), leading to different compute-vs-memory balance and thus different optimal rescale pipelines. The Pareto frontier for each (workload, phase) pair occupies a different region of the accuracy--energy plane. This two-dimensional workload-dependence---across phases \emph{and} application domains---is the key validation of our framework.
    \item We target $\sim 2\times$ \textbf{total energy reduction} relative to the NVFP4-like two-level FP32-rescale reference for workload-optimal configurations. We do not require every selected point to dominate MXFP4: the sweep should reveal when MXFP4-like bit-shift scaling is already the right hardware point, and when another phase-specific configuration is worth the extra datapath support.
\end{enumerate}

\subsection{Current Solutions and Related Work}

Current 4-bit schemes each bundle a fixed rescale pipeline, applied uniformly to both prefill and decode (Table~\ref{tab:existing}).

\midrule
INT4-GPTQ  & 1 & FP16+zp     & g=128       & FP16 dequant \\
MXFP4      & 1 & E8M0        & b=32        & Bit-shift \\

HiFloat4   & 3 & E6M2+E1+E1  & hierarchical & Mixed \\

It is important to distinguish between two categories of quantization work. \textbf{Format-level schemes} (NVFP4, MXFP4, HiFloat4, MX+, M$^2$XFP) define a fixed data layout and a simple, regular arithmetic pipeline---block scaling, multiply, accumulate, rescale---that maps directly to dedicated hardware: shifters, fixed-precision multipliers, and accumulators. Each configuration fully specifies a \emph{synthesizable datapath}. In contrast, \textbf{algorithm-level methods} (SmoothQuant, GPTQ/AWQ, QuIP) involve complex runtime logic---per-channel activation migration, Hessian-based weight rounding, incoherence processing---that is inherently sequential and data-dependent, making them unsuitable for dedicated hardware pipelines. Our search space operates exclusively at the \textbf{format/datapath level}: every point in the space corresponds to a concrete, hardware-realizable MMA pipeline with no complex control logic, just as NVFP4 and MXFP4 do today.

Among format-level works, all recent proposals share a common limitation: \textbf{each produces a single fixed design applied uniformly to all inference phases.} HiFloat4 fixes its three-level hierarchy as a single format; AXE optimizes accumulator precision in a software-only PTQ framework without hardware cost modeling; MixPE performs Pareto DSE over dequantization \emph{placement} but does not touch the internal rescale pipeline structure; M$^2$XFP \cite{m2xfp} and MX+ \cite{mxplus} enhance MX through metadata augmentation, each producing one new fixed scheme. None considers that prefill and decode have fundamentally different compute-vs-memory profiles and may benefit from different pipeline configurations.

\textbf{What's missing:} (1) A structured DSE formulation decomposing the rescale pipeline into orthogonal dimensions. (2) Phase-aware evaluation that separately models hardware cost under prefill and decode regimes. (3) The insight that the optimal configuration is phase-dependent, making phase-adaptive quantization both feasible and necessary.

\subsection{Our Approach: Phase-Adaptive Quantization via Search Space Decomposition}

We decompose the 4-bit MMA datapath into independently tunable dimensions, define a structured search space, and evaluate each configuration under \textbf{both prefill and decode regimes} to identify phase-specific optima. Critically, every configuration in our search space specifies a \textbf{hardware-friendly, regular datapath}---block scaling followed by multiply-accumulate followed by rescale---with no data-dependent branching or complex control logic. Each point can be directly implemented as a fixed-function pipeline in silicon, just as NVFP4 and MXFP4 are today. We fix weight format (E2M1) and activation format (FP16/FP8) and focus on three core dimensions:

\textbf{Dimension 1: Rescale pipeline structure}---the number of rescale levels (0, 1, or 2) and block granularity at each level ($b \in \{16, 32, 64, \text{per-channel}\}$; for 2-level, coarse $B \in \{256, \text{per-channel}, \text{per-tensor}\}$). Finer granularity and more levels improve accuracy but add rescale operations and scale-factor storage.

\textbf{Dimension 2: Scale-factor format} (per level, independently)---FP32, FP16, BF16, FP8 E4M3, E8M0 (power-of-2 bit-shift, nearly free), or fixed-point. In a 2-level pipeline the fine and coarse levels may use different formats, e.g., E8M0 shift at fine level + FP16 at coarse level.

\textbf{Dimension 3: Accumulator precision}---FP32, FP16, BF16, INT32, or segmented (accumulate $N$ partial products in FP16, then reduce to FP32).

After pruning invalid combinations (e.g., accumulator precision $\geq$ operand precision), we estimate $\sim$50 viable configurations.

\subsubsection{Locating existing schemes}
Every existing scheme is a single hand-designed point in this space:
\begin{itemize}
    \item \textbf{NVFP4} = \{2-level (b=16, B=tensor), FP32 rescale $\times$2, FP32 acc\}
    \item \textbf{MXFP4} = \{1-level (b=32), E8M0 shift, FP32 acc\}
    \item \textbf{INT4-GPTQ} = \{1-level (g=128), FP16 dequant, FP32 acc\}
    \item \textbf{HiFloat4} = \{3-level (hierarchical), E6M2+E1+E1, FP32 acc\}
\end{itemize}

Our contribution is the \textbf{search space definition and phase-decoupling methodology}: decomposing the bundled pipeline into this search space, evaluating under both prefill and decode regimes, and demonstrating when an existing bundled scheme is suboptimal and when it is already close to the knee of the frontier. The observed optima differ across workload/phase cells, validating the need for workload-aware and, for LLM/VLA, phase-adaptive quantization.

\subsection{Tradeoffs and Challenges}

\begin{itemize}
    \item \textbf{Search space tractability:} Pruning reduces the combinatorial space to $\sim$10--20 viable configurations, manageable for exhaustive sweep under both regimes.
    \item \textbf{Phase switching cost:} Supporting two quantization modes requires either two sets of quantized weights in memory or runtime requantization. In practice, scale-factor storage overhead is modest relative to the weight tensors themselves.
    \item \textbf{Design-time commitment:} The accelerator's compute units are fixed at design time. Phase-adaptive quantization requires the datapath to support at least two rescale modes---we show this is feasible with minimal area overhead.
\end{itemize}

\textbf{Key findings} (Figures~\ref{fig:sweep}, \ref{fig:overhead}):

\begin{enumerate}
    \item \textbf{NVFP4 is energy-beneficial for decode but energy-harmful for prefill.} During decode, the bandwidth savings from 4-bit weights outweigh the rescale overhead (0.90$\times$ energy). During prefill, the rescale pipeline's 74\% energy share pushes total cost \emph{above} FP16 (1.27$\times$).
    \item \textbf{Rescale overhead dominates the gap to ideal.} The full NVFP4 pipeline costs 2.8--3.9$\times$ more energy than the bare FP4 MatMul. This gap is the optimization target for our search space.
    \item \textbf{Latency scaling differs drastically.} In decode, the NVFP4 pipeline adds 9.4$\times$ latency overhead vs.\ ideal (many extra einsums on a small $M{=}1$ workload). In prefill, latency overhead is only 1.16$\times$ because the large MatMul dominates cycles. This confirms the qualitatively different bottleneck structure.
\end{enumerate}

\subsection{Baselines, Workloads, and Fair Comparison}

We compare against NVFP4 and MXFP4 as baselines---the two dominant hardware-friendly 4-bit formats---evaluated under both prefill and decode regimes. All configurations use 4-bit weights; effective compression ratio (including scale-factor overhead) is reported. $M$ varies to represent prefill ($M = 128$) vs.\ decode ($M = 1$).

To validate that optimal configurations are \emph{workload-dependent}, we evaluate across \textbf{three application domains} with distinct GEMM shape profiles (Table~\ref{tab:workloads}):

These domains differ in their GEMM dimension profiles: LLM FFN layers have large $N$ and $K$; VLM vision encoders have moderate, balanced dimensions; VLA action heads have small $N$ with large $K$. Different $(N, K)$ profiles lead to different compute-vs-memory balance, and thus different optimal rescale configurations.

\textbf{Accuracy metrics:} We use two levels of evaluation. (1) \emph{Per-layer:} cosine similarity between quantized and FP16 layer outputs ($\text{cos\_sim} = \frac{\langle Y_q, Y_{16} \rangle}{\|Y_q\| \cdot \|Y_{16}\|}$), which captures numerical fidelity without requiring end-to-end inference. (2) \emph{End-to-end} (when feasible): perplexity for LLM, task accuracy for VLM, success rate for VLA.

\subsection{Experiment 1: Phase-Dependent Energy Bottleneck Analysis (Done)}

\textbf{Goal:} Demonstrate that prefill and decode have qualitatively different energy bottleneck structures.

\textbf{Status: Completed.} Our preliminary results (Section~III, Figures~\ref{fig:energy}--\ref{fig:overhead}) confirm: rescale accounts for 74\% of prefill energy vs.\ 64.5\% of decode energy. NVFP4 costs 1.27$\times$ FP16 in prefill energy but only 0.90$\times$ in decode. This asymmetry directly motivates phase-specific search.

\textbf{Class concepts:} Compute-bound vs.\ memory-bound regimes; energy cost hierarchy; arithmetic intensity.

\subsection{Experiment 2: Cross-Workload Search Space Sweep (Done)}

\textbf{Goal:} For each of the three workloads, sweep the search space under both prefill and decode, and show that (a) the Pareto-optimal configuration can differ between phases within a workload, and (b) the optimal configuration also differs \emph{across} workloads.

\textbf{Method and status: Completed.}
\begin{enumerate}
    \item \emph{Hardware cost:} For each candidate configuration $\times$ workload $\times$ phase, run AccelForge evaluation with the workload's representative GEMM shapes. Extract energy per output element and latency.
    \item \emph{Accuracy:} For each configuration, run the quantization emulator on representative tensor snapshots. Measure per-layer output cosine similarity against FP16. End-to-end task metrics remain future work.
    \item \emph{Joint Pareto analysis:} For each (workload, phase) pair, plot all configurations on the accuracy--energy plane. Draw Pareto frontiers; mark NVFP4-like C7 and MXFP4-like C1 as reference points.
\end{enumerate}

\textbf{Class concepts:} Design-space exploration; Pareto optimality; phase-aware hardware-software co-design.

\textbf{Metrics \& visualization:} The completed grid of Pareto plots has 3 workloads $\times$ 2 phases = 6 panels. Each panel shows all search-space configurations as scatter points, with the Pareto frontier highlighted and C1/C7 marked. The key visual is that the frontier shape and knee-point differ across panels; C7 is consistently high energy, while C1 is often a strong low-energy point rather than an interior point.

\textbf{Observed trends:}
\begin{itemize}
    \item \textbf{LLM} (large $K$): Prefill selects C1, the cheap one-level E8M0 configuration. Decode selects C8, which spends slightly more energy than C1 but clears the cosine floor with FP16 accumulation.
    \item \textbf{VLM} (balanced $N, K$): Both phases select C1. For this workload, the cheapest MXFP4-like point is already the best fixed and phase-adaptive choice under the 0.98 cosine floor.
    \item \textbf{VLA} (small $N$, latency-critical): Decode selects C8 for accuracy, while prefill selects C9, a hybrid two-level E8M0+FP16 configuration. This workload shows the clearest gain over a best-fixed strategy.
    \item \textbf{Cross-workload divergence:} The six cells select three distinct configurations (C1, C8, C9), confirming that quantization design should be workload-specific and selectively phase-adaptive.
\end{itemize}

\subsection{Experiment 3: Workload-Adaptive Gain Quantification (Done)}

\textbf{Goal:} Quantify the end-to-end efficiency gain of workload-and-phase-adaptive quantization over a single fixed scheme.

\textbf{Method and status: Completed.} For each workload, compute the efficiency of three strategies:
\begin{itemize}
    \item \emph{Fixed-NVFP4:} Use NVFP4 for both phases (status quo).
    \item \emph{Best-fixed:} Use the single best configuration from the search space for both phases.
    \item \emph{Phase-adaptive:} Use separate Pareto-optimal configurations for prefill and decode.
\end{itemize}
Weighted energy: $E = \alpha \cdot E_{\text{prefill}} + (1 - \alpha) \cdot E_{\text{decode}}$, where $\alpha$ depends on deployment scenario (e.g., $\alpha{=}0.3$ for chatbot, $\alpha{=}0.8$ for batch processing, $\alpha{=}0.5$ for VLA real-time control).

\textbf{Class concepts:} Workload characterization; design-time specialization; system-level optimization.

\textbf{Metrics \& visualization:}
\begin{itemize}
    \item[(a)] Table: best configuration for each (workload, phase) pair, with energy and accuracy (cos\_sim). The 6 cells contain 3 distinct configurations.
    \item[(b)] Bar chart: energy savings of phase-adaptive vs.\ fixed-NVFP4 and vs.\ best-fixed, per workload.
    \item[(c)] Line plot: X = $\alpha$, Y = energy savings, one curve per workload. Phase-adaptive consistently beats fixed NVFP4-like C7; it beats best-fixed only when the workload actually has phase-divergent optima.
\end{itemize}

\textbf{Observed outcome:} Phase-adaptive quantization yields 50--60\% weighted energy reduction over fixed NVFP4-like C7 across all three workloads and evaluated prefill weights. Relative to the best fixed configuration, the gains are workload-dependent: about 0.6\% for LLM, 0\% for VLM, and 8.2\% for VLA at the default $\alpha$ values. Crucially, no single configuration from the search space is best across all 6 (workload, phase) cells---\textbf{validating that the search space and per-workload search methodology are both necessary}. The zero phase-adaptive gain for VLM is not a failure; it shows that the framework can identify when one simple mode is sufficient.
